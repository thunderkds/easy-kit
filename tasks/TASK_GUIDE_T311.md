## Requirement (Pillar 1 — Adapt the requirement)

User, 2026-11-14, after the Supervisor built a private artifact "Easy Kit Atlas" that shows every agent and skill with its steps in order: "is it possible to add this one to the detail docs, it looks good now". The Supervisor took "the detail docs" to be `site/docs.html`. The user then chose, from two options each:
- Data source: **generated by a script, with a test that fails when the page is stale** (not a hand-pasted snapshot).
- Placement: **a new section after Skills** (not a replacement of `#skills`).

This task is the first half: the data and the stale check. T312 builds the section that reads the data.

**Restated intent** (Supervisor's interpretation, in the project's domain language):
> A script reads `agents/*.md`, `skills/*/SKILL.md` and the stage index of `AGENTS.md`, and writes one JSON data block into `site/docs.html`. A test runs the script in check mode and fails when the block no longer matches the kit. T312 draws the explorer from that block.

**Out of scope** (what this task explicitly does NOT do):
- Any visible change to `site/docs.html`: no section, no nav link, no CSS, no script that reads the block (T312).
- A change to any agent or skill file, to `AGENTS.md`, or to `site/theme.css`.
- Hand-written step text. Every string in the block comes from a kit file, EXCEPT the stage and one-line description of the five built-ins, which the generator holds in its `BUILTINS` dict because `AGENTS.md` names them and gives neither.
- A new dependency. The script uses the Python standard library only.

## Approach

**Pattern reference**: the `settings-catalog` block in `site/docs.html` (an inline `<script type="application/json">` that a later script reads), and `scripts/lane_check.py` for the shape of a small standard-library script with a check mode.
**Vital slice**: the generator, the marker block, and the `--check` test. The extraction rules are fixed by the prototype below.
**Cut list**: no watch mode, no output other than `site/docs.html`, no hook that runs the generator on commit (the test is the guard), no data for `agents/general-agent-template.md`, no per-skill byte size.

Extraction rules (all text only; they come from the Supervisor's 2026-11-14 prototype that built the private Easy Kit Atlas artifact, which read 37 skills and 4 agents with them):
- Front matter: `name`, `description`, `tools`, `model`. Strip `**` and backticks; turn `[text](url)` into `text`.
- Skill steps: step headings are searched from the first `## Workflow|Process|Steps|Protocol|Procedure` heading to the end of the file (the whole body when there is none): each `###`/`####` heading that begins with `Step`, `Phase`, `Stage` or a number is a step; its note is the first line under it, cut at about 260 characters on a word boundary with `…`. With fewer than two such headings, take the numbered list items of that section (only this fallback stays inside the section) (`title — note`). With still fewer than two, `kind` is `sections`: every `##`/`###` heading except `Role`, `Karpathy`, `Communication`, `Edge Cases` and `Failure Modes`, with its first line as the note. At most 12 steps.
- Agents: `startup` = the numbered list under `## Mandatory Startup`; `checklist` = the bullets of the first of `Implementation checklist`, `Evaluation checklist`, `Environment Health Checklist`, `Responsibilities`; `escalation` and `skills` = the table rows (header and separator rows dropped) under `## Complexity & escalation` and `## Available skills`; `boundaries` = bullets under `Scope boundaries` or `Constraints`; `comms` = the first paragraph under `## Communication Protocol`.
- Titles never start with a dash or a step number.

Known limit: the stale check cannot see a change to a built-in's stage or description, because the dict is in the script.

Risk: Medium. The block sits in a public page. The test must prove the block cannot close its own script tag, and that no home directory or secret leaks from a kit file into the page.

## Edge Case Checklist

- [ ] A `SKILL.md` with no front matter, or no `## Role:` line: the entry still appears, with an empty `role`.
- [ ] A skill name that is not in the `AGENTS.md` stage index and not a built-in: it goes to group `any`, never dropped.
- [ ] The stage index line changes shape: `--check` exits 1 with `stale:`, and the generator exits 2 with one line saying it cannot read the index. It never writes a half-empty block.
- [ ] Windows line endings in a source file: the output is the same.
- [ ] The marker comments are missing from `site/docs.html`: the generator exits 2 and writes nothing.
- [ ] Pin-test pre-flight: the `Pre-existing pin tests` row below is filled before work starts
- [ ] Stale references: grep `docs/claude-md/`, `site/`, `README`, `scripts/validate.sh`, `.github/` for a list of scripts, a "scripts/" count or a CI step that must now name the new script
